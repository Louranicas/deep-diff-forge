# DDF-2026-007: GitLab tokens and fine-grained GitHub tokens were not found

| | |
| --- | --- |
| Severity | Not rated by an assessment. A released ranking signal missed a kind of credential its own list of forge tokens leaves out: a patch that adds a GitLab token or a fine-grained GitHub token. The patch's paths, sections, hunks and lines were shown as before; the label `secret_like` and its +5 were not |
| Affected | 0.5.0 (the first release with `secret_like`) to 0.9.0. Measured on 2026-11-23 on the published 0.8.3 binary, the 0.8.4 release binary (`0c93b3ed…`) and the 0.9.0 release binary (`5ba0a366…`); 0.5.0 to 0.8.2 were not run, and the source of every tag from `v0.5.0` to `v0.9.0` names none of the prefixes below |
| Fixed in | 0.10.0. What stays open is under "What 0.10.0 does not change" |
| Found | 2026-11-22, while checking an outside review of 0.9.0 that listed the GitLab and fine-grained GitHub forms as missed (plan of record S3.24) |
| Published | With the tag `v0.10.0` |

## What went wrong

`secret_like` reads every added line, strings and comments included, for a private key header
or a token by its fixed prefix and the least run of its bytes after it: `AKIA`, the classic
GitHub prefixes `ghp_`, `gho_`, `ghs_`, `ghu_`, `ghr_`, the Slack prefixes and `sk_live_`. The
list had no GitLab prefix and not the prefix of GitHub's fine-grained personal access tokens,
which GitHub has issued beside the classic `ghp_` tokens since 2022. A GitLab personal, deploy,
runner, pipeline trigger, CI job or OAuth application token, or a fine-grained GitHub token,
added to a source file, a configuration file or a comment, ranked without the label.

## What this could cause

A patch that commits a forge credential ranks without the label and its +5, so a reviewer who
relies on the ranking or the label may look elsewhere first, and a policy that refuses
`secret_like` (forge-warden's, for example) lets the patch through. Measured on 2026-11-23
(`--stdin-patch --rank --json`), each form in three places (a Rust string, a `.env`
assignment, a YAML comment), bodies drawn at random when the test runs and never written down;
"the fix" is the 0.10.0 candidate (commit `fe94ad10`):

| Form | 0.8.3 | 0.8.4 | 0.9.0 | the fix |
| --- | --- | --- | --- | --- |
| `ghp_` and 36 bytes (control) | 3 of 3 | 3 of 3 | 3 of 3 | 3 of 3 |
| `AKIA` and 16 bytes (control) | 3 of 3 | 3 of 3 | 3 of 3 | 3 of 3 |
| `glpat-` and 20 bytes | 0 of 3 | 0 of 3 | 0 of 3 | 3 of 3 |
| `glpat-` routable (27 bytes, `.01.`, 9 bytes) | 0 of 3 | 0 of 3 | 0 of 3 | 3 of 3 |

No output of any version repeated a token.

## How to check a version

`deep-diff-forge --version` prints the version. This command builds a patch that adds one
made-up GitLab token (twenty bytes after its prefix, assembled when it runs, so no token is
written here) and ranks it; nothing is applied, so it is safe to run:

```sh
python3 -c 'print("diff --git a/.env b/.env\nnew file mode 100644\n--- /dev/null\n+++ b/.env\n@@ -0,0 +1,1 @@\n+TOKEN=gl" + "pat-" + "Ab3d" * 5)' | deep-diff-forge --stdin-patch --rank --json
```

0.8.3, 0.8.4 and 0.9.0 give the file score 4 and the signal `new_file` only; 0.10.0 adds
`secret_like` at new line 1 (score 9). The output holds the line number, not the token.

## What 0.10.0 changes

- Seven rows join the prefix list; the eleven rows before them are unchanged, so every line an
  earlier version called a secret still is one. GitLab: `glpat-` (a personal access token; its
  routable form, `glpat-` then a longer payload, `.01.` and a check part, is found by the same
  row), `gldt-` (deploy token), `glrt-` (runner token), `glcbt-` (CI job token) with at least
  20 bytes of letters, digits, `_` and `-` after the prefix; `glptt-` (pipeline trigger token)
  with at least 40; `gloas-` (OAuth application secret) with at least 64. GitHub: `github_pat_`
  with at least 82 bytes of letters, digits and `_`.
- The prefix must start the token: a letter or a digit just before it is a different word.
  Only the line number goes into the evidence, as before; the token is never copied out.
- Measured over the 7,421 patches of the comparison corpus: no item lost against 0.9.0's
  `secret_like`. None of the 2,086 patches of this repository's and forge-warden's history
  gained one. 186 patches gained an item, every one a made-up input: 180 of a generated battery
  of the new forms in sixteen spellings, five probes of the new forms, and one probe whose
  `glpat-` is followed by twenty `-`, which the byte class reads as a token. Over that battery
  each form is found in a string, a raw string, a constant, parentheses, `format!`, Python,
  `.env`, TOML and Markdown, and not when split over two strings, in other case or a byte
  short, as for the eleven earlier rows.

## What 0.10.0 does not change

- **Forms that are not read**, stated in the `secret_like` row of
  [docs/reference/risk-ranking.md](../reference/risk-ranking.md): a token split over two
  strings or built by code, a prefix in other case, a body shorter than the least run, and
  the other GitLab prefixes (feed, incoming mail, agent, SCIM and similar tokens).
- A made-up value of the right shape (a placeholder of twenty `x`, an example in a document) is
  labelled as a token would be: the rule reads shapes, not whether a credential is live.
- No evidence means no token was found, never that a change is safe.

## What to do

1. Use 0.10.0 from the signed tag `v0.10.0`: its release archive checked against the signed
   `SHA256SUMS` (`scripts/release_local.sh verify`), or a build of the tag.
2. Until then, and for patches already reviewed with 0.5.0 to 0.9.0, search the added lines
   for the prefixes, for example
   `grep -nE '(^|[^A-Za-z0-9])(gl(pat|dt|rt|ptt|cbt|oas)-|github_pat_)' FILES`, and treat each
   hit with a long run after it as a credential: revoke it at the forge and remove it from the
   history.

## Found by

An outside review of 0.9.0 (2026-11-21) listed GitLab tokens and fine-grained GitHub tokens as
forms `secret_like` misses. The coordinator checked the claim on a frozen 0.10.0 candidate
binary, and it was measured again on the published and release binaries before this advisory
was written. Details: [CHANGELOG](../../CHANGELOG.md) (Unreleased, Fixed), plan of record S3.24.
