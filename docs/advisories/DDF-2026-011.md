# DDF-2026-011: `agent doctor --gate` and `eval` passed when the reader of their output had gone

| | |
| --- | --- |
| Severity | Not rated by an assessment. Two released checks failed open: `agent doctor --gate` (a chain that is not ready) and `eval` (a failing case) exited 0 instead of 7 when the reader of standard output had closed before their document was written, with nothing on standard error. The document itself was right; only the exit code a script reads was wrong |
| Affected | `eval`: 0.8.3 to 0.10.0. `agent doctor --gate`: 0.9.0 (where `--gate` first shipped) and 0.10.0; 0.8.3 and 0.8.4 have no `--gate` (exit 2). Measured on 2026-11-23 on the comparison corpus's binaries of 0.8.3 (`4cafd0ad…`), the 0.8.4 release (`0c93b3ed…`), 0.9.0 (`5ba0a366…`) and the 0.10.0 release binary (`df8359c4…`), three runs each; `eval` before 0.8.3 (it exists from 0.5.0) was not measured |
| Fixed in | 0.11.0 (task F7.h2: one door to exit 7) |
| Found | 2026-11-23, by reading the code while DDF-2026-010 was fixed; named as a known issue in the 0.10.0 release notes |
| Published | With the tag `v0.11.0` |

## What went wrong

`eval` writes its receipt, and `agent doctor` its checks, to standard output and decide their
exit 7 after the document is written. Every write to standard output goes through one function
that treats a broken pipe (a reader that has gone, as `… | head -1` that has finished, or a
supervisor that closed its end) as a clean exit 0, so the process exited 0 there and never
reached the refusal. 0.10.0 fixed the same order for `findings verify --require-findings` and
`--require-all` only ([DDF-2026-010](DDF-2026-010.md)).

With standard output at a file that cannot be written (`>/dev/full`) the same commands exited 3
("write failed") instead of 7, which a script that reads 3 as an environment problem can retry
until it passes.

## What this could cause

A script that runs `agent doctor --gate | head -1` (or `eval | head`) and decides by the exit
code took a chain that would not judge a stop, or an engine that failed its labelled corpus,
for ready. Measured on 2026-11-23, three runs per cell: the exit code and what standard error
held (`refused` a `refused:` line, `error` an `error:` line, `empty` nothing). "The fix" is the
0.11.0 branch (`integrate/0.11.0` with 0.10.0 merged). `eval` ran on a one-case corpus whose
ranking case cannot hold; `agent doctor --gate` ran outside any Git repository.

| Command | stdout | 0.8.3 | 0.8.4 | 0.9.0 | 0.10.0 | the fix |
| --- | --- | --- | --- | --- | --- | --- |
| `eval`, a failing case | open | 7, empty | 7, empty | 7, empty | 7, empty | 7, refused |
| `eval`, a failing case | reader gone | **0**, empty | **0**, empty | **0**, empty | **0**, empty | 7, refused |
| `eval`, a failing case | `/dev/full` | 3, error | 3, error | 3, error | 3, error | 7, refused |
| `agent doctor --gate`, no repository | open | 2 (no `--gate`) | 2 (no `--gate`) | 7, error | 7, error | 7, error and refused |
| `agent doctor --gate`, no repository | reader gone | 2 | 2 | **0**, empty | **0**, empty | 7, error and refused |
| `agent doctor --gate`, no repository | `/dev/full` | 2 | 2 | 3, error | 3, error | 7, error and refused |

## How to check a version

`deep-diff-forge --version` prints the version. Outside any Git repository run (nothing is
changed, so it is safe):

```text
python3 -c 'import os,subprocess,sys; r,w=os.pipe(); os.close(r); p=subprocess.run(sys.argv[1:], stdout=w); print(p.returncode)' deep-diff-forge agent doctor --gate
```

0.9.0 and 0.10.0 print 0; 0.11.0 prints 7 and writes `error: the chain is not ready: …` and
`refused: N checks failed (agent doctor)` to standard error.

## What 0.11.0 changes

- Exit 7 has one door: every refusal is decided before its document is written, and every
  failed write to standard output goes through it. A write error of any kind (a reader that has
  gone, a full disk) while a refusal is pending writes the refusal's reason lines to standard
  error and exits 7; with none pending a broken pipe is still a clean exit 0 and any other write
  error exits 3.
- Every exit 7 names its reason class in one line `refused: <text> (<tag>)`: `eval` writes
  `refused: N cases failed (eval)`, `agent doctor` writes `refused: N checks failed (agent
  doctor)` after its `error:` line ([refusal reasons](../reference/output-and-exit-codes.md#refusal-reasons-exit-7)).

## What to do

1. Use 0.11.0 once it is released from its signed tag.
2. Until then, a script that runs `agent doctor --gate` or `eval` reads their output to its end
   (or sends it to a file that can be written) before it takes the exit code, so the process
   never meets a closed reader; or it reads `ok` of the doctor's `--json` document and
   `failures` of the eval receipt.
