## What changed

- **A turn that always comes** (VD4R15-M-1). Two asks are made before any other at every stop: the slow-lane commit asked least recently, then the fast-lane commit asked least recently (`Ask`, `sorted_commits`, `judge_commits`, `ASK_OWED`, `State.stops`). A slow-lane ask that fails does not count toward the three failures that end the asking. **Invariant, in the doc comment and held by a test that counts submissions from the judge's log:** every commit without a verdict is submitted to the judge at least once in every N stops, N the number of the session's commits with no verdict (a slow-lane commit once in S stops, a fast-lane commit once in F). Preconditions: the judge can be run, the state can be kept, three seconds are left after the working trees.
- **A working tree is known as itself** (VD4R15-M-2, HR7-H-1, HR7-L-2). A linked tree's identity is its administrative directory's inode with the inode and mtime of its `commondir` file (`instance_of`, `tree_instance`, `linked_instances`); nothing is written into the repository; the failure key holds no path and no label. Entries of trees Git no longer lists are forgotten. The transition table is the test `a_working_tree_is_known_by_what_it_is_not_by_where_it_is`, with real Git: `worktree move` and `mv` + `repair` stand; remove and add at the same path blocks, also with the same failure text (it is a new tree); a tree removed for good is forgotten; two trees whose long paths display alike each block.
- **A failure is known line by line** (HR7-M-1). What is remembered for a tree's staged and uncommitted units is the set of failing lines (rule, signal, path) with the count seen. A stop blocks for a line that is not remembered or whose count has grown; otherwise it stands. Lines gone are forgotten, so a line that comes back blocks; a count that fell is remembered lower. The block says "New at this stop:" and "Stands beside it, as said before". A failure of more than 256 lines is remembered as one. Table: `what_is_left_of_a_failure_does_not_block_again`.
- **One writer at a time** (VD4R15-M-3, HR7-L-4). Every stop takes the session's lock, the first too (the lock file is named from the session id). An advice hook writes under the lock, onto the state as it then is, and only what it has said; a session-start that cannot have the lock in two seconds records nothing and says so; an advice hook that cannot have it in 0.3 s writes and prints nothing.
- **The counting lines are never cut** (HR7-L-1): they are built and measured first; the upper part takes what is left. Live: 70 failing commits are 26 named and "and 44 more commits fail."
- **Said at every stop** (HR7-L-3): "(a failure stands there)" is part of a tree's name on the counting line.
- **A linked tree inside the project** is a working tree of it, not a nested repository (HR7-L-5). **A hold for a note keeps the judge's first words** (HR7-L-6; judged-file line `id:h:rules|words`). Whole rule names with "(+N more)". State schema v7; a v6 state is not read.
